# ADR-0002: 미리보기를 사진 합성 밑그림 + AI 사진화로 만든다

- 상태: 채택
- 날짜: 2026-11-28
- 일부 대체: ADR-0001의 렌더링 부분("장면을 웹에서는 SVG로, 서버에서는 PNG로 그린다")

## 배경

posy에서 가장 큰 제품 위험은 **미리보기가 실제 꽃다발처럼 예쁘게 보이느냐**다. 꽃 선물 초보가 결과를 믿고 꽃집에 가져갈 수 있어야 한다.

ADR-0001은 장면 데이터를 코드로 그린 SVG 일러스트로 보여 주는 것을 전제로 했다. Phase 2를 시작하기 전에 레포 밖에서 시안을 만들어 검증했다.

1. 코드로 그린 SVG 꽃 일러스트: "실제 꽃으로 보여야 한다"는 이유로 탈락
2. 배경을 지운 꽃 사진을 레이아웃대로 붙인 합성: SVG보다 낫지만 사진처럼 보이지 않음
3. 합성 이미지를 이미지 편집 AI로 사진처럼 바꾸기: 만족. 이 방향으로 아래 모델들을 비교했다

### 충실도 기준

AI가 바꾼 결과는 **꽃 종류, 색, 송이 수를 반드시 유지**해야 한다. 꽃 위치는 더 예뻐진다면 바뀌어도 된다. 사람이 원하는 구성을 더 보기 좋게 다듬어 주는 것이 이 서비스가 있는 이유이기 때문이다.

### 검증 결과 (2026-11-26 ~ 27)

같은 합성 밑그림 3종(장미 10송이 / 튤립 5 + 장미 2 / 장미 1송이)으로 비교했다.

| 후보 | 실행 환경 | 결과 |
|---|---|---|
| Gemini 이미지 편집 | Gemini 앱(수동) | 사진 품질 만족. 종류나 색이 바뀐 경우가 있음. API는 장당 비용 |
| SDXL + ControlNet(canny) img2img | Colab T4, 장당 18초 | 송이 수는 유지하지만 사진처럼 바뀌지 않음 → 탈락 |
| Qwen-Image-Edit-2511 (4단계 LoRA) | HF Space | 종류·색 유지, 품질 Gemini 수준. 장미 10송이가 9/8/9로 나옴. 게스트 한도 때문에 더 시험할 수 없음 |
| **Qwen-Image-Edit-2511 (GGUF Q4 + 4단계 LoRA)** | **개인 데스크톱 RTX 3060 Ti 8GB, ComfyUI, 장당 약 57초** | **9장 중 9장 송이 수 일치.** 종류 유지, 품질 Gemini 수준. 남은 문제: 연핑크·진핑크 비율이 한 송이씩 바뀜, 일부 진핑크가 작약처럼 풍성해짐 |

남은 문제의 원인은 주로 **꽃 재료의 색이 애매한 것**이었다(중간 핑크 장미, 주황빛 노란 튤립). 재료 색을 이름과 정확히 맞추는 것이 품질을 좌우한다.

## 결정

1. 미리보기는 두 단계로 만든다.
   - **밑그림**: `bouquet-core`가 장면(꽃별 위치·회전·크기·레이어 순서·포장지)을 계산하고, `crates/render`가 꽃 재료 이미지를 장면대로 합성해 PNG로 만든다. 요청 즉시 보여 준다.
   - **사진화**: 개인 데스크톱의 **AI 워커**가 밑그림을 Qwen-Image-Edit-2511로 사진처럼 바꾼다. 완성되면(약 1분) 화면의 밑그림을 사진으로 바꾼다.
2. AI 워커는 **API 서버에 먼저 접속해서 작업을 가져간다(풀 방식)**. 데스크톱을 인터넷에 열지 않는다. 데스크톱이 꺼져 있거나 GPU를 다른 일(게임 등)에 쓰는 동안에는 작업이 대기한다.
3. **꽃 재료(한 송이 이미지)도 데스크톱의 오픈 모델로 만든다.** 조명·각도·배경을 통일하고 색을 이름에 정확히 맞출 수 있고, 저작권 출처 표기가 필요 없다. 실제로 가능한지는 Phase 4에서 검증하고, 안 되면 이 결정을 새 ADR로 다시 정한다.
4. 웹은 장면을 직접 그리지 않고, API가 준 **밑그림 PNG와 사진 PNG를 보여 주기만** 한다.

## 고려한 대안

| 대안 | 장점 | 채택하지 않은 이유 |
|---|---|---|
| 코드로 그린 SVG (ADR-0001 전제) | 즉시, 결정적, 비용 0 | 실제 꽃처럼 보이지 않아 제품 목적을 못 채움 |
| 사진 합성만 (AI 없음) | 즉시, 결정적, 충실도 완벽 | 사진처럼 보이지 않음. 대신 밑그림으로 쓴다 |
| Gemini API | 품질 좋음, 운영 부담 없음 | 장당 비용, 종류·색이 바뀌는 사례. **데스크톱을 쓸 수 없을 때의 대비책**으로 남긴다 |
| SDXL + ControlNet | 빠름, 구조 유지 | 사진처럼 바뀌지 않음 |
| 클라우드 GPU 임대 | 항상 켜져 있음 | 포트폴리오 규모에서 월 비용이 큼 |

## 결과

좋은 점

- 운영 비용 0원으로 Gemini 수준의 사진 미리보기를 만들 수 있다.
- 밑그림 단계는 그대로 결정적이라 테스트하기 쉽고, 사용자는 기다리는 동안에도 구성을 바로 확인한다.

감수할 점

- **결정성 범위가 줄어든다.** "같은 입력 + 같은 seed → 같은 결과"는 밑그림까지만 보장한다. AI 결과는 만들 때마다 조금씩 다를 수 있으므로, 한 번 만든 결과를 **입력 + seed + 모델·워크플로 버전**과 함께 저장하고 다시 쓴다(공유 링크도 저장된 결과를 보여 준다).
- 사진화에 약 1분이 걸린다. 화면은 밑그림을 먼저 보여 주고 상태를 알려 줘야 한다.
- 데스크톱 한 대에 의존한다. 꺼져 있거나 게임 중이면 사진화가 늦어진다. 대기 상태 표시와 Gemini API 대비책으로 보완한다.
- AI가 송이 수나 색을 틀릴 수 있다. 밑그림의 겹침을 줄이고, 나중에 결과의 송이 수를 자동으로 검사해 다시 만드는 단계를 검토한다.
- 모델 파일과 ComfyUI 설정이 레포 밖(데스크톱)에 있다. 워커 단계에서 설치 방법과 워크플로를 레포에 문서로 남긴다.
